The pipeline.

Five stages, one Rust core, compiled twice. Nothing is approximated twice — so browser and desktop cannot disagree.

Stage 01 · parse

The container opens, nothing is thrown away

OPC is unzipped entry by entry. Every part — even ones Quire has never seen — is claimed, content-addressed, and held for write-back. Unknown is not the same as absent.

Stage 02 · model

A canonical model, not a DOM shadow

Paragraphs, runs, styles and section geometry resolve into one typed model. It is a read-only projection — the write-back path never touches it, so modelling gaps can never corrupt your file.

Stage 03 · shape

Real metrics, not character widths

Text runs through shaping against embedded/subset fonts: kerning, CJK advance widths, fallback chains. Widths here are the widths everywhere.

Stage 04 · break

Knuth–Plass: one optimum per paragraph

Break points are chosen jointly across all lines to minimise total badness — UAX#14 decides where a break is legal, KP decides where it is right.

Stage 05 · paginate

One keystroke ≠ re-paginate the chapter

Paragraph-level caches reflow only the dirty interval; page breaks settle in background passes. p95 incremental reflow: under 8 ms. The output is a display list — both renderers draw from the same numbers.

無損不是承諾，而是結構：一個 Office 檔案是數千個宣告的容器，引擎未觸碰的每一個宣告、每一條 ZIP entry、每一個位元組，都會在寫回時原樣出現。瀏覽器分頁與桌面共用同一個排版核心：相同的整形advance、相同的最佳化斷點、相同的 display list。沒有任何計算被近似兩次，因此也不可能出現分歧——你現在看到的這一行，與原生端渲染的是同一個答案。Every line here is justified by distributing glue between words, exactly as the engine's own display list would place it.
